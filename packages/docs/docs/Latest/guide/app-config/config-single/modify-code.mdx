# Modify Code as Needed

We provide React SPA and Next.js implementations. The following content will be explained in two technology stacks. You can choose to read according to your preference.

## React SPA

> Note: For brevity, all path representations in this section omit the `packages/react-app` prefix. For example, `src/App.tsx` actually refers to `packages/react-app/src/App.tsx`.

### 0. Select Running Mode

In the previous section [Choose the Mode That Suits You](./select-mode.md), we have already selected the application mode.

By default, the running mode in the code is "multi-app". You can see the code for initializing global runtime configuration in `src/App.tsx`:

```tsx title="src/App.tsx"
// Initialize global runtime configuration
difyChatRuntimeConfig.init('multiApp');
```

If you want to run in single application mode, you need to modify the parameter of `difyChatRuntimeConfig.init()`:

```tsx title="src/App.tsx"
// Initialize global runtime configuration
difyChatRuntimeConfig.init('singleApp');
```

### 1. Custom Application Configuration Management

By default, for demonstration purposes, we use LocalStorage for application configuration storage. You can see this in `src/services/app`:

Multi-app mode:

```tsx title="src/services/app/multiApp/index.ts"
import DifyAppService from './localstorage';

export const appService = new DifyAppService();
```

Single-app mode:

```tsx title="src/services/app/singleApp/index.ts"
export { appConfig } from './localstorage';
```

In `src/services/app`, there are two directories: `multiApp` and `singleApp`, each with three implementation forms for application configuration storage:

- `static-readonly`, Data hardcoded in code, only supports querying, does not support modifying data
- `localstorage`, Uses LocalStorage storage, supports full CRUD, but cannot sync across browsers
- `restful`, Stores through API interfaces, supports full CRUD, recommended🌟

You can choose according to your needs, or modify the code or extend other implementation forms. Finally, just export through `src/services/app/multiApp/index.ts` or `src/services/app/singleApp/index.ts`.

#### 1.1 Custom Restful Implementation

If you need to customize your backend service, please follow the steps below.

First, refer to `packages/server` and implement the following interfaces:

- Get App configuration list
- Get App configuration details
- Add App configuration
- Update App configuration
- Delete App configuration

Then create a new file in `src/services/app/multiApp`, just inherit the abstract class `DifyAppStore` and implement all its methods, calling the corresponding interfaces in the above service.

#### 1.2 Display Fixed Application List Data

Modify the data in `src/services/app/multiApp/static-readonly/data.ts`.

```ts title="src/services/app/multiApp/static-readonly/data.ts"
import { AppModeEnums, IDifyAppItem } from '@dify-chat/core'

/**
 * Static application list for demonstration
 */
export const staticAppList: IDifyAppItem[] = [
	{
		// Application unique identifier, just ensure it's not duplicated
		id: '0.270357011315995',
		info: {
			// Application name
			name: 'My Chatflow APP',
			// Application description
			description: 'My Chatflow Application',
			// Tags
			tags: [],
			// Application type
			mode: AppModeEnums.CHATFLOW,
		},
		// Application request configuration
		requestConfig: {
			// Dify API prefix
			apiBase: 'https://api.dify.ai/v1',
			// Dify API key
			apiKey: 'app-xxxxxxx',
		},
	},
]
```

## Next.js

### 0. Select Running Mode

In the previous section [Choose the Mode That Suits You](./select-mode.md), you should have selected the application mode as needed. Let's start configuring.

> Note: For brevity, all path representations in this section omit the `packages/nextjs-app` prefix. For example, `.env.template` actually refers to `packages/nextjs-app/.env.template`.

Copy `.env.template` to `.env` file:

```bash title=".env"
cp .env.template .env
```

By default, the running mode in the code is "multi-app". You can modify it in `.env`:

<Tabs>
  <Tab label="Multi-App Mode">
```bash title=".env"
RUNNING_MODE=multiApp
```
	</Tab>
  <Tab label="Single-App Mode">
```bash title=".env"
RUNNING_MODE=singleApp
```
	</Tab>
</Tabs>

### 1. Select Storage Method

By default, we use the file system for application configuration storage. You can see the specific storage method used in `services/app/index.ts`:

```ts title="services/app/index.ts"
# Use fs implementation
export * from "./fs";
```

Under the `services/app` directory, two storage forms for application configuration are implemented:

- `fs`, File-based storage, supports full CRUD, but has the risk of data loss
- `restful`, Manages through API interfaces, supports full CRUD, recommended🌟

You can choose according to your needs, or modify the code or extend other implementation forms. Finally, just export through `services/app/index.ts`.
