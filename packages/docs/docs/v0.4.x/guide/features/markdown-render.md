## Reply Forms

Dify supports configuring reply forms for users to fill in through `jinja2`, and this project also supports corresponding functionality.

Dify Chatflow configured reply content example:

```html
<form data-format="json">
  <label for="username">Username:</label>
  <input type="text" name="username" value="{{ username }}" />
  <label for="phone">Contact Phone:</label>
  <input type="text" name="phone" value="{{ phone }}" />
  <label for="content">Complaint Content:</label>
  <textarea name="content"></textarea>
  <button data-size="small" data-variant="primary">Submit</button>
</form>
```

> Note:
>
> - You need to correctly handle `sys.query` logic in Chatflow yourself, distinguishing between normal messages, messages that trigger forms, and submission information.
> - The `data-format` attribute of the form tag is used to specify the format of form data. Currently, `json` and `text` formats are supported.

After replying with the above content, by default, when users click the form's submit button, the form's value object will be sent as a message to the same Dify application and displayed in the message list. Example text of the submission message:

```json
{
  "username": "lexmin",
  "phone": "13123456789",
  "content": "Delivery is too slow, I want to report",
  "isFormSubmit": true
}
```

Among them, the `isFormSubmit` field is used to identify this as a form submission message. You can use it in Chatflow's conditional branches to judge message types.

![Reply Form](/guide__sample_form.png)

### Customize Submission Message Text

If you don't want to display the specific form value json string, but need to customize the sent message text, you can follow the instructions below to configure it in the application configuration (this configuration only affects the interface display, the actual submission to the Dify Chatflow start node is still the form value json string filled in by the user).

**Multiple Application Mode**

Fill in the fields in the add/update application configuration popup:

- Form Reply - Set to "Enabled"
- Submission Message Text - Text used to replace the form value object, such as "I submitted a form"
