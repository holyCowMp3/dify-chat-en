# Conversation Input Parameters

Dify applications support configuring initial parameters, which are displayed on the interface for user input when a conversation starts.

By default, the same conversation only allows inputting parameter values once. In subsequent conversations, the input controls will be disabled.

![Application Input Parameters - Default](/sample_app_input_disabled.png)

## 1. Support Updating Parameters After Conversation Starts

In the application configuration, you can choose whether to allow users to update parameter values after the conversation starts.

Edit the application configuration in the interface, and set "Update Historical Parameters" in "Conversation Parameter Configuration" to "Enabled".

![Application Input Parameters - Configuration](/sample_app_input_setting.png)

### Read URL as Application Parameters

In actual application scenarios, we may need to dynamically pass parameter values in the URL and fill them into the form.

![Read URL as Application Parameters - Description](/sample_app_input_intro.png)

To support this functionality, your URL needs to be defined in the following form:

```shell
<dify-chat-address>/dify-chat/app/<appId>?<paramName>=<encodedParamValue>&isNewCvst=1
```

#### Application Example - Order Number Fill

By default, the conversation parameter value is empty:

![Read URL as Application Parameters - Default](/sample_app_input_default.jpg)

We can concatenate parameters in the URL:

```shell
http://localhost:5200/dify-chat/app/${appId}?orderNo=${encodedValue}&isNewCvst=1
```

Description:

- `appId`, Application ID
- `encodedValue`, Parameter value processed by `Gzip` and `encodeUriComponent`
- `isNewCvst`, Specify whether to start a new conversation (if not specified and historical conversations exist, the most recent conversation will be selected by default)

`encodedValue` generation method (NodeJS):

```javascript
import zlib from 'zlib'

const originalOrderNo = "123456";
const buffer = Buffer.from(originalOrderNo, "utf8");
let encodedValue = "";

zlib.gzip(buffer, (err, compressedBuffer) => {
  if (err) {
    console.error("Error during compression:", err);
    return;
  }
  const encodedString = compressedBuffer.toString("base64");
  encodedValue = encodeURIComponent(encodedString);
  console.log("Compressed Base64:", encodedValue);
});
```

After filling `encodedValue` into the link and accessing it, you can see that our defined `orderNo: 123456` has been filled into the form:

![Read URL as Application Parameters - Result](/sample_app_input_filled.jpg)

## 2. Global Parameter Cache

Sometimes, for some fixed business parameters, we may need to share output parameter values across multiple applications/conversations without requiring users to repeatedly input them. In this case, you can use the global parameter cache functionality.

Using the global parameter cache is very simple. Just add `&isKeepAll=true` while passing parameters normally.

For example:

```bash
http://localhost:5200/dify-chat/app/cmdx5fmtb0000364zs23s6nez?orderNo=H4sIAAAAAAAAEzM0MjYxNQMAYdNyCQYAAAA%3D&isNewCvst=1&isKeepAll=true
```

Parameter description:

- `isKeepAll`, Specify whether to cache parameter values for reuse when entering other conversations
  - `true`, Cache parameter values

The entire link will have the following effects:

- Start a new conversation (`isNewCvst=1`)
- Cache parameter values (`isKeepAll=true`)
	- After entering other conversations, the `orderNo` parameter value will be automatically filled into the form
