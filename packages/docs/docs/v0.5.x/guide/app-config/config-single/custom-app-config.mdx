# Custom Application Configuration

## Determine Running Mode

Before starting configuration, ensure your running mode is single application mode.

<Tabs>
  <Tab label="React SPA">
```tsx title="packages/react-app/src/App.tsx"
// Initialize global runtime configuration
difyChatRuntimeConfig.init('singleApp')
```
	</Tab>
  <Tab label="Next.js">
```bash title="packages/nextjs-app/.env"
# Running mode
RUNNING_MODE=singleApp
```
	</Tab>

## Custom Application Configuration

Dify Chat has built-in multiple application configuration management methods to meet different scenario needs. You can choose the appropriate method according to your needs.

### React SPA Version

#### Configuration Entry

```tsx title="packages/react-app/src/services/app/singleApp/index.ts"
// Default uses LocalStorage storage
export { appConfig } from './localstorage'
```

#### Built-in Implementations

**1. LocalStorage**

Uses LocalStorage for data storage and modification. When users switch browsers, data will be lost. Only for demonstration purposes.

**2. Static Data**

Uses static data for storage, only supports querying, suitable for scenarios where users don't need to customize applications.

Define configuration:

```ts title="packages/react-app/src/services/app/singleApp/static-readonly/data.ts"
import { AppModeEnums } from '@dify-chat/core'

/**
 * Static application configuration for demonstration
 */
export const staticAppConfig = {
	id: '0.270357011315995',
	info: {
		name: 'My Chatflow APP',
		description: 'My Chatflow Application',
		tags: [],
		mode: AppModeEnums.CHATFLOW,
	},
	requestConfig: {
		apiBase: 'https://api.dify.ai/v1',
		apiKey: 'app-xxxxxxx',
	},
}
```

**3. Restful API**

Gets and modifies data through interfaces, recommended🌟

The default backend service address is `http://localhost:5300`. You can modify it according to your needs.

If your backend service address is different from the default address, just modify the BaseURL called in the corresponding restful implementation.

```ts title="packages/react-app/src/services/app/singleApp/restful.ts"
// For example, your custom backend service address is http://localhost:4567
const API_BASE_URL = 'http://localhost:4567'
```

You need to implement the following interfaces yourself to complete application configuration reading and saving:

| Interface Name | Request Method | Interface Path | Request Parameters | Return Parameters |
|---------|----------|----------|----------|----------|
| Get App Configuration Details | GET | `/app` | None | `IDifyAppItem` |
| Save App Configuration | POST | `/app` | `IDifyAppItem` | None |

### Next.js Version

#### Configuration Entry

```ts title="packages/nextjs-app/services/app/singleApp/index.ts"
// Use fs implementation
export { appConfig } from "./fs";
```

#### Built-in Implementations

**1. Local File Storage**

Uses local files for storage, supports reading and modification, but has the risk of data loss.

Configuration example:

```json title="packages/nextjs-app/.dify-chat/storage/app.config.json"
{
  "info": {
    "name": "Chatflow Demo",
    "description": "",
    "tags": [
      "Parameter",
      "Test"
    ],
    "mode": "advanced-chat",
    "author_name": "Dify"
  },
  "requestConfig": {
    "apiBase": "https://api.dify.ai/v1",
    "apiKey": "app-xxx"
  },
  "answerForm": {
    "enabled": false
  },
  "inputParams": {
    "enableUpdateAfterCvstStarts": false
  },
  "extConfig": {
    "conversation": {
      "openingStatement": {
        "displayMode": "default"
      }
    }
  },
  "id": "1751257572123"
}
```

**2. Restful API**

Manages through API interfaces, supports reading and modification, recommended🌟

The default backend service address is `http://localhost:5300`. You can modify it according to your needs.

If your backend service address is different from the default address, just modify the BaseURL called in the corresponding restful implementation.

```ts title="packages/nextjs-app/services/app/singleApp/restful.ts"
// For example, your custom backend service address is http://localhost:4567
const API_BASE_URL = 'http://localhost:4567'
```

You need to implement the following interfaces yourself to complete application configuration reading and saving:

| Interface Name | Request Method | Interface Path | Request Parameters | Return Parameters |
|---------|----------|----------|----------|----------|
| Get App Configuration Details | GET | `/app` | None | `IDifyAppItem` |
| Save App Configuration | POST | `/app` | `IDifyAppItem` | None |
